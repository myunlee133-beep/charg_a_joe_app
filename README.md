# 찾아줘 iOS + 서울대 식단 크롤러

## 셔틀·퀘스트·분실물 통합

2026-10-31 실제 병합 이력을 보존한 [GitHub 통합 브랜치](https://github.com/myunlee133-beep/charg_a_joe_app/tree/build/found-items-integrated-20261031)에 반영했습니다. 기존 main과 두 기능 브랜치는 보존합니다. Appetize의 현재 실행본은 통합 전 빌드입니다.

## 통합 습득물 변경

지도 숫자를 누르면 선택한 보관 위치의 분실물 목록을 엽니다. 목록에서 각 물품의 상세·수령 확인을 볼 수 있고, 새로고침 시 같은 위치에 새로 들어온 물품과 다른 곳으로 이관된 물품을 현재 위치로 구분합니다. 거점 카드의 `이 위치의 습득물 보기`도 제공합니다. `codex/shuttle`·`codex/quest`와의 충돌 결과와 통합 시 보존할 내용은 [브랜치 확인 문서](BRANCH_COMPATIBILITY.md)에 정리했습니다. 두 브랜치를 통합해 충돌을 해결했으며 main과 원래 기능 브랜치는 보존합니다.

지도 목록 추가본은 [Swift 검사 24개·iOS 빌드·시뮬레이터 설치 및 실행](https://github.com/myunlee133-beep/charg_a_joe_app/actions/runs/41092075947)을 통과했습니다. 선택한 위치의 상세 화면에서 지도를 열면 위치 목록도 닫고 해당 지도 위치로 돌아갑니다. 로그인 뒤 실제 숫자 터치의 전체 화면 검사는 별도 확인 대상입니다.

최신 지도 목록 빌드는 2026-10-31 01:45(KST) Appetize에 업로드했습니다. 지도 카드의 목록 버튼이 하단 탭 바에 가려지지 않도록 보완했고, 실제 Appetize에서 거점 카드 → 선택 위치 목록 → 선택한 지도로 복귀를 확인했습니다. 인증된 물품 내용은 로그인 후 표시합니다.

2026-10-31 추가 수정: 목록의 등록처 필터를 **현재 보관 장소 5개(101동 분실물센터, 67동 두레문예관, 셔틀버스 분실물 보관소, 기타, 관악경찰서)**로 교체했습니다. MySNU와 운영진 직접 등록 자료는 모두 `운영진`으로 표시하되 내부 출처·원본 번호는 보존합니다. 경찰서 이관 후 실제 수령 여부는 경찰서 기록과 연동되지 않아 알 수 없다고 목록·상세에 안내합니다.

실제 MySNU **8월 24건·9월 16건을 추가**해 기존 10월 18건과 합계 58건을 저장했습니다. 8월 24건은 원문의 월별 이관 공지에 따라 관악경찰서 위치·`police` 상태이며 실제 수령 완료로 단정하지 않습니다. 9월·10월 34건은 확인된 교내 보관 위치를 사용합니다. 부분 범위 수집(`p_complete=false`)이므로 다른 물품의 상태는 바꾸지 않습니다.

331동 차량정비고의 셔틀버스 보관처를 기본 안내·지도와 `backend/lost_found/003_shuttle_storage_center.sql`에 추가했습니다. [학교 공식 안내](https://aerospace.snu.ac.kr/board/notice?bbsidx=23230&bm=v)는 2014년 자료이므로 현재 운영시간·보관·이관 일정은 방문 전 확인하도록 표시합니다. 실제 수령처가 바뀐 물품은 발견 장소와 관계없이 현재 보관 장소로 분류합니다.

자동 수집에 필요한 운영 세션·서버 키·실행 환경·전체 목록 검증·하루 3회 예약·실패 시 처리 방법은 이미 [수집기 README](crawler/lost_found/README.md)에 있습니다. 이 수정으로 자동 수집이나 인증 정보 저장을 켜지는 않습니다.

이번 변경은 Python 54개, PostgreSQL 회귀·추가 자료 트랜잭션 검사와 [macOS의 Swift 21개 검사·iOS 빌드·시뮬레이터 실행](https://github.com/myunlee133-beep/charg_a_joe_app/actions/runs/41083172959)을 통과했습니다. 로그인 뒤 새 필터의 전체 화면 조작 검사는 별도로 필요합니다.
2026-10-31 00:51(KST) 새 iOS 빌드를 Appetize에 업로드하고 분실물 탭·331동 보관처 안내를 확인했습니다. [Appetize 실행](https://appetize.io/app/ios/org.chargajoe.chajajwo?device=iphone14pro&osVersion=17.2&toolbar=true).

최초 10월 물품 18건과 이번 8·9월 추가 자료 모두 원문 게시물 번호·제목·등록일·설명·확인된 보관 위치를 사용하고 출처를 MySNU로 저장했습니다. 원문 사진은 포함하지 않았습니다. [더미 데이터 16건](backend/lost_found/demo/README.md)은 이력을 보존하면서 목록·지도에서 숨겼습니다. 새로고침하면 실제 자료가 조회됩니다. 학교 세션·서버 키를 저장하거나 상시 자동 수집을 연결하지는 않았습니다. 수집 CLI 기본 실행은 검증만 하며 실제 DB 반영에는 `--apply`가 필요합니다.

분실물 탭은 습득물 등록·통합 조회·소유자 확인·실제 수령 확인만 제공합니다. 찾아달라는 분실 의뢰 등록은 제거했으며 기존 퀘스트의 분실물 찾기 유형을 이용합니다. 수령 완료 물품은 목록과 지도에서 제외하고 DB 이력은 보존합니다. 사진은 선택, 보관 위치는 필수이며 경찰서 이관 시 실제 이관 장소와 좌표로 갱신합니다. 지도는 확대 수준별로 개수를 묶어 표시합니다.

통합 DB 마이그레이션을 실제 Supabase에 적용했고 기존 기록을 보존했습니다. macOS에서 Swift 테스트 14개·iOS 빌드·시뮬레이터 실행을 통과했으며 Appetize에도 수정본을 업로드했습니다. **사용자의 최종 선택에 따라 마이스누 자동 수집은 연결하지 않았습니다.** GitHub에 인증 정보를 저장하지 않았고 예약 실행도 제거했습니다. 현재 앱에는 사용자·운영진 등록 및 수령 확인을 제공하며, MySNU 신규 게시물이 자동으로 추가되지는 않습니다. [수집 코드와 제한](crawler/lost_found/README.md)은 향후 연결을 위한 참고로 남겼습니다.


- `ios/` — SwiftUI 앱. 식당 핀과 식단 시트는 `https://chajajwo-web-mu.vercel.app/api/meals`에서 최신 식단을 받아 오고, 실패하면 저장본/번들(`Resources/meals.json`)을 씁니다. `xcodegen`으로 `project.yml`에서 프로젝트를 만듭니다.
- `crawler/` — 서울대 식단 크롤러(`chajwo_meals`). 웹 저장소의 GitHub Actions가 이 코드로 `data/meals.json`을 하루 3번 갱신합니다.

홈 지도에 퀘스트 목록·상세, 교내순환 실시간 기반 추정 위치와 정류장을 표시합니다. 식단은 식당 탭에서 조회하며 커뮤니티 탭의 본문은 비워 두었습니다. 퀘스트 수락·등록·제출은 실행 중의 로컬 시연 기능입니다. [화면 범위, 셔틀 데이터와 검증 방법](design-drafts/quest-home/README.md)을 확인하세요.

`swift test`로 지도·추적·퀘스트 모델을 검사하고, GitHub Actions에서 iOS Simulator 빌드와 홈 화면 실행을 확인합니다.

습득물 등록과 경찰서 이관의 장소명은 건물명·구분자·상세 위치를 합쳐 서버와 동일하게 2~120자로 검사합니다. 화면에 전체 글자 수를 표시하고 초과하면 저장을 막고 안내합니다. 결합 문자와 이모지도 PostgreSQL `char_length`와 같은 기준으로 계산합니다.

Mac에서 장소명 회귀 검사는 다음과 같이 실행하며, iOS CI에서도 자동 실행합니다.

```sh
swiftc ios/Chajajwo/LostFoundRules.swift ios/Tests/LostFoundRulesTests/main.swift -o /tmp/lost-found-rules-tests
/tmp/lost-found-rules-tests
```
