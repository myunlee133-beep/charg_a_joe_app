# 찾아줘 사랑방 — Supabase 백엔드 설치

본 폴더는 **로컬 모형이 아니라 실제 회원 간 공용 게시글을 저장하기 위한 서버 스키마**입니다. GitHub에 코드를 올리는 것만으로 서버가 자동 생성되지는 않습니다.

## 사용 전 준비

1. Supabase에서 별도 프로젝트를 생성하고 Auth > Providers에서 Email을 활성화합니다. 실서비스에서는 메일 인증을 유지하고, SMTP/비밀번호 제한/가입 요청 제한을 설정합니다.
2. Supabase SQL Editor에서 `001_community_mvp.sql` 전체를 실행합니다. 새 프로젝트 또는 충분한 검토를 거친 프로젝트에서만 실행하세요.
3. 앱의 `ios/Chajajwo/Info.plist`의 `COMMUNITY_SUPABASE_URL`에 프로젝트 URL(예: `https://example.supabase.co`), `COMMUNITY_SUPABASE_PUBLISHABLE_KEY`에 **publishable 또는 legacy anon 공개키만** 설정합니다. `xcodegen generate`를 사용하는 경우 같은 두 값을 `ios/project.yml`에 설정해야 덮어써지지 않습니다. **service_role/secret 키는 앱에 절대 추가하지 마세요.**
4. 회원가입과 메일 인증 후 로그인합니다. 로그인 뒤 닉네임을 설정할 수 있습니다.
5. 초기 운영진을 별도로 지정하려면 SQL Editor에서 다음 쿼리의 UUID를 실제 가입 회원 UUID로 바꿔 실행합니다. 권한을 앱에서 직접 부여하지 마세요.

```sql
update public.community_profiles set role='moderator'
where user_id = '00000000-0000-0000-0000-000000000000'::uuid;
```

## 적용 기능

- 이메일·비밀번호 회원가입/로그인/메일 확인, 키체인 기반 로그인 유지/토큰 갱신, 닉네임 변경, **사랑방 계정 삭제**
- 소통(자유·질문) 및 선의(정보 공유), 검색, 태그 필터, 페이지별 추가 로드
- 익명·닉네임 개별 선택 게시·댓글, 본인 글·댓글 삭제, 추천·스크랩
- 회원 신고·작성자 차단/해제, 운영진 신고 처리 및 게시물 숨김
- 선의 게시글 정보 유형(경험/학습/공식/생활), HTTPS 출처, 정보 유효기간
- 운영진의 출처 확인/추천/반려 기록과 승인 기여 이력 (보상 금액·지급 기능은 없음)
- 단순 서버 작성 빈도 제한(글 10분에 5개, 댓글 10분에 20개, 신고 하루에 20개)

## 보안 설계와 주의

- `community_*` 테이블에 직접 SELECT/INSERT/UPDATE/DELETE 권한을 부여하지 않으며, 인증된 사용자만 `community_*` RPC를 호출할 수 있습니다.
- 공개 RPC 응답에는 작성자의 `author_id`, 이메일, 학교 인증 데이터가 들어가지 않습니다. 운영진이 운영 목적으로만 확인할 내부 테이블은 앱 API에 열지 않습니다.
- `display_mode`가 익명인 경우 서버가 이름을 `익명`으로 반환합니다. 익명 게시와 닉네임 게시의 내부 식별자는 계정 소유권 확인과 제재·기여 이력에만 사용됩니다.
- 앱이 사용하는 Supabase 공개키는 사용자별 JWT와 정책을 반드시 함께 사용해야 합니다. 본 SQL은 RLS뿐 아니라 직접 테이블 권한을 제거하고 서버 RPC만 공개합니다.
- 백엔드에 이미 이름이 같은 객체가 있다면 SQL의 `CREATE TABLE IF NOT EXISTS`가 기존 구조를 교체하지 않습니다. 새 DB에서 최초 적용하거나 별도 마이그레이션을 작성하세요.
- 학교 이메일 인증/SSO, 저작권 자동 판정, 콘텐츠 필터링 자동화, 이미지·PDF 업로드, 푸시 알림, 기여 보상 지급, 관리자 다중 권한은 **이번 MVP에 포함되지 않습니다.**
- 앱 스토어 출시 전에는 금지 콘텐츠 필터링, 운영자 연락 수단, 신고 처리 SOP, 이용약관·개인정보 처리방침·저작권 요청 대응 체계, 재가입/봇/스팸 대응을 추가 검토하세요.
- `community_delete_account`는 커뮤니티 인증 계정과 서버 내 커뮤니티 데이터를 삭제합니다. 기존 앱의 분실 신고와 식단 캐시는 기기 로컬에 따로 남아 있으므로 앱 전체 사용자 데이터 삭제 정책은 향후 통합이 필요합니다.
