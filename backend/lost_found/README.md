# 찾아줘 분실물 MVP — Supabase 설치 및 테스트

**기준 저장소**: `myunlee133-beep/charg_a_joe_app`, 2026-10-28 확인 시 `community` 브랜치 PR #2가 열린 상태. 이 코드는 `community` 브랜치의 최신 코드를 기준으로 작성했으며 기존 GPS 및 사랑방 코드를 포함합니다.

## 설치 (기존 Supabase 프로젝트 그대로 사용)

1. **기존 사랑방 SQL을 이미 실행했다면 다시 실행하지 않습니다.** Supabase의 **SQL Editor → New query**에서 `backend/lost_found/001_lost_found_mvp.sql` 전체를 **한 번 실행**합니다. 이 SQL은 기존 `community_*` 테이블과 충돌하지 않습니다. 운영 DB라면 SQL을 검토하고 백업 후 실행하세요.
2. Table Editor에서 `lf_centers`, `lf_found_items`, `lf_lost_requests`, `lf_claims`, `lf_leads` 테이블이 생성됐는지 확인합니다. 공식 센터 정보 2개가 시드됩니다.
3. iOS `Info.plist`와 `project.yml`의 `COMMUNITY_SUPABASE_URL`(루트 URL, **`/rest/v1` 붙이지 않음**) 및 `COMMUNITY_SUPABASE_PUBLISHABLE_KEY`에 기존 설정을 **유지**합니다. 새 키는 필요하지 않습니다. PR 전용 ZIP에는 사용자의 로컬 설정값이 포함되어 있지 않으므로 기존 파일을 덮어쓰기 전에 백업하세요.
4. iOS 앱에서 `분실물` 탭 또는 홈 지도 `분실물` 필터로 진입합니다. 로그인은 기존 사랑방 계정과 동일하며, 센터 위치·기본 운영 안내는 로그인 전에도 볼 수 있습니다.
5. Windows에서는 `chajajwo-lost-found-verification.ipynb`의 오프라인 검사를 먼저 실행할 수 있습니다. 실제 Supabase DB 연동 및 카카오맵 렌더링은 본인의 Supabase 프로젝트/실제 iOS 기기에서 별도로 테스트해야 합니다.

## 3단계 기능

- **1단계**: 서울대 공식 확인 장소 101동 아시아연구소 1층 분실물센터 및 67동 두레문예관 201호 임시 보관처. DB에 위경도(건물 대표 좌표), 층/호수, 전화번호(확인된 경우만), 평일 운영시간, 주말·공휴일 안내, 공식 출처, 확인 날짜 저장. 공개 위치 안내는 네트워크 연결 실패 시 앱 내 기본 정보로 유지.
- **2단계**: 회원이 발견 물품 종류·이름·공개 설명·발견 건물·시간·보관 상황을 등록. 서버 DB에 저장되고 회원 목록·지도에 표시. 실제 공식 보관처로 인계했을 때만 ‘센터 인계’ 선택. 소유자는 비공개 특징으로 확인 요청 가능하며, 이후 요청 상태(대기/승인/반려)를 본인 화면에서 확인할 수 있습니다. 등록자는 상태 변경 가능.
- **3단계**: 회원이 분실 물품 종류·이름·특징·마지막 확인 장소·시간을 등록해 다른 회원에게 공개. 다른 회원이 자신의 습득물과 의뢰를 연결해 제보. 분실자는 완료 처리 가능.

## 신뢰성과 개인정보

- 기존 홈 지도에 있던 `hub1~hub3`는 **예시 가상 거점**이므로 지도에서 숨겼습니다. 기존 앱의 위치·카카오맵 엔진과 건물 검색·식당·사랑방 기능은 유지합니다.
- 현재 DB의 분실물센터는 **관악캠퍼스에서 공식 자료로 확인된 2개 지점**입니다. 다른 서울대 캠퍼스 및 학내 부서별 임시 보관처 전체가 검증됐다는 뜻은 아닙니다.
- 101동 **분실물센터 평일 운영 09:00~18:00**와 캠퍼스안전반 **연중 24시간 당직**은 서로 다른 개념입니다. 토요일·일요일·법정 공휴일에 분실물 수령이 가능한지 확인되지 않았으므로 휴무를 단정하지 않고 **방문 전 전화 확인**을 안내합니다.
- 67동의 상세 운영시간·휴무와 전화번호는 확인되지 않아 `NULL`/미확인으로 저장합니다. **67동 습득물만 2영업일 임시 보관 후 공식 센터로 이관**합니다.
- 신규 등록 글은 모두 **회원 제보**로 표시하며 공식 습득물 데이터라고 표기하지 않습니다. 지도 핀은 건물 대표 좌표(실제 출입구 좌표 아님)입니다.
- 내부 `author_id`, 소유권 확인용 비공개 문구는 공개 목록에 반환하지 않습니다. 테이블 직접 접근은 차단하고 서버 RPC로 조회·수정합니다.
- 사진 업로드·실시간 채팅·배송·보상·자동 매칭·실시간 푸시는 **이번 MVP 범위 밖**입니다.

## 최초 연결 이후 점검

- SQL 실행 후 `lf_centers_list` RPC가 2개 결과를 반환하는지 확인합니다(로그인 없이 호출 가능).
- 서로 다른 **테스트 계정 A/B**로, A가 습득물을 등록하고 B가 목록/지도 조회 및 소유권 확인 요청을 할 수 있는지 검증합니다.
- B가 A의 습득물 상태를 변경하거나 A에게 전달한 비공개 소유권 확인 내용을 제3자가 조회할 수 **없어야** 합니다. B는 `lf_my_claims`에서 자신의 요청 상태만 확인할 수 있어야 합니다.
- B가 분실 의뢰를 작성하고 A가 자신의 습득물을 해당 의뢰에 연결할 수 있는지, B에게 제보가 표시되는지 검증합니다.
- 실제 iOS Xcode 빌드·Kakao Maps SDK POI 표시 및 터치 이벤트 검증은 **macOS와 iPhone**이 필요합니다.
