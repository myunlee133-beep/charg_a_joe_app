# 분실물 화면 확인용 더미 데이터

현재 앱 DB의 이 자료는 실제 MySNU 최근 물품 18건을 등록한 뒤 보관 종료 처리했습니다. 아래 SQL은 선택적 테스트 참고 자료이며, 앱에 다시 자동 생성되지 않습니다.

`seed.sql`은 기존 통합 DB에 **관리자가 선택해서** 넣는 가상 물품 16건입니다. 자동 마이그레이션에 포함하지 않습니다. 모든 제목에 `[테스트]`, 모든 설명에 실제 분실물이 아니라는 안내가 붙습니다. 사진과 실제 개인정보는 포함하지 않습니다. 출처는 사용자 등록이며 MySNU 수집물로 위장하지 않습니다.

| 구성 | 수량 | 확인할 내용 |
| --- | ---: | --- |
| 101동 동일 좌표, 보관 중 | 6 | 최대 확대에서도 숫자 표시 유지 |
| 인접한 67동 동일 좌표, 보관 중 | 3 | 지도 확대에 따라 101동과 분리 |
| 63동 동일 좌표, 보관 중 | 2 | 같은 장소의 개수 표시 |
| 62동·301동 보관 중 | 각 1 | 가까운 건물과 먼 건물의 분리 |
| 관악경찰서 이관 | 2 | 경찰서 위치와 이관 상태 |
| 수령 완료 | 1 | 목록·지도에서 제외 |

따라서 처음 넣으면 앱에는 가상 물품 **15건**이 표시됩니다. 8가지 물품 종류를 모두 포함합니다. 건물 좌표는 앱의 캠퍼스 자료, 경찰서 좌표는 확인된 위치 목록을 사용했지만 각 물품과 보관함은 모두 가상입니다.

## 적용

인증을 완료한 기존 테스트 계정 UUID를 준비하고 Supabase SQL Editor에서 다음을 **한 번에 같은 트랜잭션으로** 실행합니다. 키나 비밀번호를 입력하는 작업이 아닙니다.

```sql
BEGIN;
SELECT set_config('chajajwo.demo_owner_id','여기에 테스트 계정 UUID',true);
-- 여기에 seed.sql 전체 내용
COMMIT;
```

지정한 테스트 계정이 작성자가 됩니다. 역할·권한은 변경하지 않습니다. 다른 회원 계정으로 수령 요청을 만든 뒤 작성자 계정에서 확인하면 실제 수령 RPC도 시험할 수 있습니다. 같은 계정은 자신의 요청을 승인할 수 없으므로 두 계정이 필요합니다.

고정 UUID와 `demo_seed` 이력으로 중복을 방지합니다. 이미 수령한 물건을 다시 보관 중으로 되돌리지 않습니다. 같은 UUID의 다른 실제 기록이 있으면 전체 생성을 중단합니다. 실제 DB 데이터와 원래 계정은 삭제하지 않습니다.

## 테스트 자료 숨기기

관리자가 `archive.sql`을 실행하면 이 자료로 확인된 가상 물품만 수령 완료로 전환되어 목록·지도에서 숨겨집니다. 그 물품의 미완료 수령 요청은 거절 상태로 정리하고, 완료된 수령과 이력은 보존합니다. 물품·수령 요청·이력은 삭제하지 않습니다. 나중에 `seed.sql`을 다시 실행해도 숨긴 자료가 자동으로 되살아나지 않습니다.

## 검증

```powershell
node backend/lost_found/tests/demo_regression.mjs
```

별도의 메모리 내 PostgreSQL에서 16건 생성, 중복 방지, 15건 목록 노출, 실제 회원 RPC의 소유자 확인·수령 완료, 재실행 시 복구 방지, 테스트 자료만 숨김을 검사합니다. 실제 Supabase Auth 로그인 자체를 대신 검증하는 검사는 아닙니다.
