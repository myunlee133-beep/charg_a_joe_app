# MySNU 분실물 수집·동기화

2026-10-31 일회성 추가 수집: 실제 8월 물품 24건과 9월 물품 16건의 목록·상세를 확인하고 수집 전후 제목·등록일·게시물 번호를 대조해 저장했습니다. 기존 10월 18건을 유지해 총 58건입니다. 8월 물품은 실제 월별 관악경찰서 이관 공지를 적용해 `police`와 확인된 경찰서 좌표를 사용합니다. 이관 이후 실제 수령 여부를 확인한 자료는 아닙니다. 범위는 부분 수집(`p_complete=false`)이며 전체 게시판 HTTP 수집·예약 실행은 여전히 연결하지 않았습니다.

> 현재 상태: 사용자가 로그인한 브라우저에서 8~10월 실제 물품 58건을 읽어 Supabase에 일회성 반영했습니다. 전체 게시판 수집이 아니므로 `p_complete=false`로 저장했고, 그 밖의 기존 물건을 수령 완료로 바꾸지 않았습니다. 테스트 물품은 별도 테스트 이력을 확인해 숨겼습니다. GitHub 인증 정보 저장과 상시 자동 수집은 켜지 않았습니다. 아래 HTTP 명령은 추후 승인된 운영 세션을 준비한 뒤 실행합니다.

## 현재 구현과 실제 연결 상태

2026-10-30 사용자가 직접 로그인한 Codex 브라우저에서 **공지 → 전체공지 → 분실물**의 목록·상세·페이지 이동을 확인했습니다. 해당 HTML 구조를 처리하는 `portal_mysnu.py`를 추가했습니다. 기존 검증 JSON 내보내기 수신 방식도 유지합니다.

관찰한 게시판 주소는 `https://my.snu.ac.kr/p/ST050102/?b=1&px=7`입니다. 목록은 `ul[data-name="post_list"]`의 `data-url`, 실제 게시물 번호, 등록일, 제목을 사용합니다. 상세 본문은 `.text_area`, 등록 시각은 `작성일`의 `dd`입니다. 관찰 당시 2,573건/129페이지였으며 첫 페이지·둘째 페이지·마지막 페이지와 일반 물건, 월별 이관 공지, 과거 이관·폐기 기록을 확인했습니다. 전체 게시글의 형식을 모두 대조 검증한 것은 아닙니다.

**현재 브라우저 로그인 상태가 서버 예약 작업으로 전달되지는 않습니다.** 쿠키를 브라우저에서 추출하거나 저장하지 않았습니다. 브라우저 화면의 상세 내용을 읽은 이번 수집은 `normalize_posts()`로 같은 정규화·위치·날짜 검사를 거친 후 기존 서버 동기화 RPC를 사용했습니다. 수집 전후 최근 목록이 같은지도 확인했습니다. 원본 사진·계정 정보·인증 값은 앱이나 소스 저장소에 넣지 않았습니다. 승인된 운영 세션과 검증된 보관처·경찰서 좌표를 운영 환경에 설정한 뒤 전체 목록 dry-run이 성공해야 상시 연결이 검증됩니다. 원본 HTTP 응답이 관찰한 DOM과 다르거나 미지원 과거 게시물이 있으면 수집 전체가 중단됩니다. 전체 원본 HTTP 수집·전체 게시판 삭제 대조·예약 실행은 아직 검증하지 않았습니다.

## 직접 게시판 수집 모드

직접 게시판을 읽는 `portal`이 CLI와 실행 함수의 기본값입니다. 과거 별도 JSON 피드는 `--source-mode export` 또는 `MYSNU_SOURCE_MODE=export`로 명시해야 합니다. 서버에 API 키를 쓰는 수집기이며, iOS 앱은 저장된 Supabase 목록을 조회합니다. 학교 로그인 세션·서버 키를 앱에 넣지 않습니다.

`locations.json`에 2026-10-30 확인한 101동 아시아연구소 분실물센터와 관악경찰서 위치를 포함했습니다. 경찰서 공식 오시는 길의 주소를 카카오맵 장소 8434805와 대조했고, 공유 링크 좌표를 표준 위도·경도로 변환했습니다. 변환은 카카오 공식 WTM 예제와 일치함을 확인했습니다. 도로 중심 좌표와 다른 임시청사로 검색된 OSM 결과는 사용하지 않았습니다. 확인 후 365일이 지나면 재확인 전까지 중단합니다. 환경 변수의 위치 목록이 비어 있으면 이 파일을 사용합니다.

- `MYSNU_COOKIE`: 운영자가 승인한 마이스누 운영 세션. 비밀번호·쿠키를 채팅이나 소스에 넣지 않습니다. GitHub Actions를 사용할 때는 암호화된 secret에 별도로 설정합니다. 세션이 만료되면 로그인을 자동 시도하지 않고 중단하며 기존 DB 상태를 유지합니다.
- `MYSNU_STORAGE_LOCATIONS`: 선택적 보관처 재정의 배열. 각 객체는 `name`, 실제 `latitude`/`longitude`, 원문에서 일치시킬 구체적 `aliases` 문자열 배열을 갖습니다. 기본 파일 밖의 보관처를 추가할 때도 실제 위치를 확인해야 합니다.
- `MYSNU_VERIFIED_POLICE_LOCATIONS`: 아래 규격의 검증된 경찰 기관 목록. 원문에서 확인한 관악경찰서도 설정이 없으면 임의 좌표로 표시하지 않습니다. 경찰청·서울경찰청(`smpa.go.kr`)·LOST112 공식 출처를 지원합니다. [관악경찰서 공식 안내](https://www.smpa.go.kr/user/nd38888.do)를 참고하되 실제 수령 창구 위치까지 확인합니다.

원본 링크를 따라 **전체 페이지의 게시물 번호·제목·날짜·총수를 수집 → 모든 상세 수집 → 전체 목록을 다시 대조**합니다. 전후 목록 불일치, 중복·누락·필터·다른 게시판, 로그인 페이지, 알 수 없는 게시글 형식, 미확인 보관처가 하나라도 있으면 DB를 호출하지 않습니다. 두 번의 목록 일치는 원본 서버의 원자적 스냅샷 보장과 같지 않으며 원본에는 그런 기능을 확인하지 못했습니다. 0건은 직접 모드에서 자동 허용하지 않습니다.

`2026년 8월분 미수령 물품 관악경찰서 이관` 같은 명시적 월별 공지는 해당 연도·월 물품을 경찰서 위치로 옮깁니다. 물건 본문의 일반적인 “1개월 후 이관” 문구로는 상태를 바꾸지 않습니다. 과거의 `관악경찰서 이관작업 完`은 경찰 이관으로, `폐기 完`은 활성 목록 제외로 처리합니다. 위치·운영시간 공지는 물건으로 생성하지 않습니다. 알 수 없는 공지를 임의로 무시하지 않습니다.

물건의 번호·입고일·설명은 본문의 수령 안내 이전 부분에서 가져옵니다. 제목에 구체적 종류가 없으면 `기타`를 사용합니다. 로그인 상태에서만 확인한 원본 사진 URL은 앱에 공개 URL로 전달하지 않으며 현재 `null`입니다. 사용자·운영진의 사진 입력은 앱에서 별도로 지원합니다. 인증 미디어를 앱에 제공하는 서버 처리는 아직 포함하지 않았습니다.

전체 게시판 수집은 최근 N건만 읽는 방식보다 오래 걸립니다. 워크플로 제한은 90분이며, 시간 초과도 삭제/수령으로 해석하지 않습니다. 첫 전체 dry-run에서 미지원 옛 게시글이 발견되면 실제 형식을 확인하여 파서를 확장한 후 재검증해야 합니다.

- [간호대학 분실물 게시판 신설 안내](https://nursing.snu.ac.kr/board/notice?bbsidx=153449&bm=v) — 2021년 안내이므로 현재 메뉴·응답 규격의 증거로 사용하지 않습니다.

`MYSNU_SOURCE_MODE=export`을 선택하면 아래 JSON 내보내기 계약을 사용합니다. `MYSNU_FEED_URL`은 마이스누의 발견된 공식 API 주소가 아니라, 실제 원본과 대조 검증한 별도 내보내기 서비스 주소입니다. 검색·최근 N일·보관 기간 제한·권한으로 숨겨진 항목이 있는 목록을 전체 목록으로 내보내면 안 됩니다.

## 실행

외부 Python 패키지 없이 Python 3.10 이상에서 실행합니다.

```powershell
python -m unittest discover -s crawler/lost_found/tests -v
python crawler/lost_found/sync_mysnu.py --dry-run
python crawler/lost_found/sync_mysnu.py --apply
```

인자를 생략해도 기본은 **읽기 검증만** 수행합니다. DB 반영에는 `--apply`가 필수입니다. `--apply`는 원본 전체를 읽기 전에 서버 설정을 먼저 검사합니다. 원본이 실패·부분 수집·변경된 경우 기존 DB를 갱신하지 않습니다.

연결할 때 로컬 PowerShell에서 다음처럼 실행할 수 있습니다. 쿠키와 서버 키는 명령 인자나 파일 대신 숨김 입력으로 받아 해당 프로세스 메모리에서만 사용합니다. 대화형 터미널이 아니면 숨김 입력을 시도하지 않습니다. 로그에 원문·쿠키·키를 출력하지 않습니다.

```powershell
$env:SUPABASE_URL = 'https://iqalavbntvadqawkegfa.supabase.co'
python crawler/lost_found/sync_mysnu.py --prompt-session --dry-run
# 검증이 끝나고 실제 저장을 진행할 때만:
python crawler/lost_found/sync_mysnu.py --prompt-session --apply
```

`--prompt-session`의 첫 입력은 **승인받은 마이스누 운영 세션 쿠키**이며 학교 비밀번호가 아닙니다. 기존 브라우저에서 쿠키를 자동 추출하거나 저장하지 않습니다. 필요한 운영 권한과 세션은 연결 시 별도로 준비해야 합니다. 원본 요청 시작 간격은 기본 0.25초이며 `MYSNU_REQUEST_INTERVAL_SECONDS`로 0.25~10초 사이에서 늘릴 수 있습니다. 전체 목록을 두 번 읽는 안전 검사는 그대로 유지합니다.

`--dry-run`은 원본 피드 전체 검증만 수행하며 Supabase를 호출하지 않습니다. 원본 레코드와 사진, 쿠키, 토큰, 서버 응답 본문은 출력하거나 파일로 저장하지 않습니다. 성공 시 개수·완전성·dry-run 여부만 출력합니다. 오류는 내용이 제한된 코드로 출력하고 종료 코드 1로 중단합니다. 네트워크 오류·로그인·잘못된 응답 뒤에는 동기화 RPC를 호출하지 않습니다.

## 설정

| 설정 | 내용 |
| --- | --- |
| `MYSNU_FEED_URL` | 검증된 내보내기 피드의 HTTPS 첫 페이지. URL 자체가 토큰을 담을 수 있으므로 GitHub **secret**으로 저장합니다. |
| `MYSNU_COOKIE` | portal 모드 필수, export 모드 선택. 승인된 학교 운영 세션. 외부 내보내기 서버에는 전달을 거부합니다. |
| `MYSNU_FEED_TOKEN` | 선택: 내보내기 서비스 자체의 인증 토큰. `Authorization: Bearer`로 전달됩니다. |
| `MYSNU_VERIFIED_POLICE_LOCATIONS` | 선택: 아래 경찰 기관 검증 목록 JSON. 기본값 `[]`. |
| `MYSNU_ALLOW_CONFIRMED_EMPTY` | 기본 허용 안 함. 전체 목록이 실제로 비었음을 운영자가 확인한 경우에만 문자열 `true`로 설정합니다. 이후 즉시 원복하세요. |
| `SUPABASE_URL` | 앱과 같은 Supabase 프로젝트의 HTTPS 원점. |
| `SUPABASE_SERVICE_ROLE_KEY` | 서버 전용 `lf_sync_mysnu` 실행 권한. 앱의 publishable/anon 키를 사용하지 마세요. 앱 번들·소스에 넣지 않습니다. |
| `SUPABASE_SECRET_KEY` | 최신 `sb_secret_...` 서버 키. 설정 시 기존 service-role 키보다 우선합니다. `apikey` 헤더로만 보내고 JWT Bearer로 보내지 않습니다. 둘 중 하나만 준비하면 됩니다. |
| `MYSNU_REQUEST_INTERVAL_SECONDS` | 원본 요청 시작 간격, 기본 `0.25`, 허용 `0.25`~`10`초. |

기존 service-role JWT도 지원합니다. 최신 secret 키를 JWT로 보내면 실패하므로 헤더를 구분합니다. [Supabase 공식 키 전환 문서](https://supabase.com/docs/guides/getting-started/migrating-to-new-api-keys)를 참고하세요. 저장 성공 시 `seen/inserted/updated/removed` 집계만 추가로 출력합니다.

모든 HTTP 리디렉션을 거부합니다. 다음 페이지는 첫 페이지와 동일한 HTTPS 원점만 허용하며, 같은 페이지 반복·응답 8 MiB 초과·잘못된 JSON·중복 JSON 키·NaN/Infinity를 거부합니다. 계정 로그인을 자동으로 시도하거나 비밀번호를 저장하지 않습니다.

## 내보내기 계약 — 원본 규격이 아닌 별도의 명시적 어댑터 규격

모든 페이지의 Content-Type은 `application/json`이어야 하며 다음 필드를 포함해야 합니다.

| 필드 | 요구 사항 |
| --- | --- |
| `schema_version` | 정수 `1` |
| `source` | `mysnu-lost-found` |
| `scope` | `all-active-items` — 아직 보관 중이거나 경찰 이관된 전체 원본 ID 목록 |
| `authenticated` | Boolean `true`; 실제 로그인·게시판 접근 성공을 확인한 경우만 |
| `retention_limited` | Boolean `false`; 검색·최근 항목·보관 기간·권한 등으로 잘리지 않아야 함 |
| `complete` | Boolean `true`; 확인된 전체 ID census에 근거한 선언. 단순히 마지막 페이지가 비었다는 의미가 아님 |
| `snapshot_id` | 전체 페이지에서 동일한 불변 스냅샷 ID |
| `snapshot_started_at` | 타임존이 포함된 ISO 8601 시각. 30분 이내, 미래 5분 이내 |
| `page` | 1부터 빠짐없이 증가하는 정수 |
| `total_pages` | 전체 페이지 수, 1~2000. 모든 페이지에서 동일해야 함 |
| `total_items` | 전체 고유 원본 ID 수, 0~100000. 모든 페이지에서 동일해야 함 |
| `items` | 아래 레코드 배열 |
| `next` | 마지막 페이지는 명시적 `null`; 나머지는 같은 원점의 다음 페이지 상대/절대 HTTPS URL |
| `empty_confirmed` | 전체 0건일 때 Boolean `true` 필수. 환경 설정의 별도 허용도 필요 |

동일 ID의 상세 정보를 새롭게 읽더라도 `source_id`를 바꾸지 마세요. 제목 해시·페이지 행 번호·수집 시각·매번 생성한 UUID는 원본 ID가 아닙니다. 전체 ID census와 상세 수집 사이에 원본이 변경되면 스냅샷 전체를 다시 읽어야 합니다. 서버가 일관된 스냅샷 기능을 제공하지 않으면 수집 전후 전체 ID 목록을 대조하여 바뀌지 않았음을 확인한 뒤 내보내야 합니다.

수신기는 각 페이지의 snapshot/count/time 일치, 페이지 누락·중복, 고유 ID 수와 총 개수를 확인합니다. 이 검사만으로 내보내기 서비스가 실제 원본 전체를 읽었다고 증명되지는 않습니다. 원본 어댑터의 완전성 검증은 운영 연결 전 필수입니다.

### 레코드

| 필드 | 요구 사항 |
| --- | --- |
| `source_id` | 안정적인 실제 게시물 ID, 공백 없는 문자열 1~128자 |
| `category` | `지갑`, `전자기기`, `학생증`, `우산`, `의류`, `가방`, `열쇠`, `기타` 중 하나 |
| `title` | 실제 제목, 양끝 공백 제거 후 2~100자 |
| `description` | 게시판에서 표시가 허용된 물건 설명, 양끝 공백 제거 후 0~1000자. 연락처·숨겨진 수령 검증 정보·세션 데이터 등은 내보내지 않음 |
| `location_name` | 원본으로 확인한 실제 보관 기관/장소, 양끝 공백 제거 후 2~120자 |
| `latitude`, `longitude` | 숫자. 위도 33~39, 경도 124~132 내 실제 보관 위치. 추정 캠퍼스 중앙 좌표 금지 |
| `registered_at` | 원본 등록 시각. 타임존 포함 ISO 8601, 수집 시각으로 대체하지 않음 |
| `status` | `stored` 또는 `police` |
| `photo_url` | 원본에서 공개 사용이 확인된 HTTPS 사진 URL 또는 `null`. 로그인 쿠키·일회용 비밀 토큰을 사진 URL에 넣지 않음 |

사진이 인증을 요구한다면 공개 URL처럼 앱에 전달해서는 안 됩니다. 승인된 서버 미디어 처리 방식이 준비될 때까지 `null`로 내보내고 이 한계를 운영자가 확인해야 합니다. 이 수신기는 이미지를 내려받거나 임의의 공개 저장소에 재배포하지 않습니다.

## 경찰 이관 위치

`경찰 이관`이라는 문구만으로 경찰서 위치를 추정하지 않습니다. 정확한 수령 기관 이름과 해당 기관의 검증된 좌표가 있어야 합니다. 기본 경찰서/캠퍼스 위치는 없습니다. `MYSNU_VERIFIED_POLICE_LOCATIONS`는 다음 필드의 객체 배열입니다.

- `name`: 원본의 `location_name`과 정확히 같은 기관 이름
- `latitude`, `longitude`: 확인된 실제 수령 장소의 좌표
- `source_url`: 기관 정보를 확인한 `police.go.kr`, `smpa.go.kr` 또는 `lost112.go.kr` 하위 공식 HTTPS 페이지
- `checked_on`: 검증 날짜 `YYYY-MM-DD`, 미래가 아니고 365일 이내

원본이 경찰 이관을 표시하면서 기관을 특정하지 않거나 검증 목록과 좌표가 다르면 수집 전체를 중단합니다. 운영자는 원본과 공식 기관 안내를 대조해 목록을 작성해야 합니다. 테스트의 가상 기관·좌표는 실제 운영 설정에 복사하면 안 됩니다.

## 서버 동기화와 사라진 게시물

전체 페이지가 모두 검증된 뒤 다음 서버 전용 RPC를 **한 번만** 호출합니다.

```text
lf_sync_mysnu(p_items jsonb, p_complete boolean, p_run_id uuid) -> JSON object
```

`p_items`는 위 레코드를 정규화한 배열, `p_complete`는 검증된 전체 스냅샷의 `true`, `p_run_id`는 새 UUID입니다. 성공 응답에는 `ok: true`가 있어야 합니다. 실제 트랜잭션·원본 ID별 갱신·원본에서 사라진 게시물의 수령 완료 처리·앱 게시물과의 분리는 백엔드 마이그레이션이 담당합니다.

**원본 게시물 삭제가 실제 수령 완료를 의미하는지 운영 규칙 확인이 필요합니다.** 삭제/숨김/보관 기간 경과/권한 변경이 혼재한 목록은 이 동기화의 전체 스냅샷으로 사용할 수 없습니다. 실패하거나 일부만 읽은 결과는 원본 삭제로 해석하지 않습니다. 앱 사용자가 직접 등록한 게시물은 원본 census에 없다는 이유로 수정하면 안 됩니다.

## 예약 실행 상태

사용자의 최종 선택에 따라 `.github/workflows/lost-found-sync.yml`의 예약 트리거를 제거했습니다. Secret도 등록하지 않았습니다. 향후 다시 연결한다면 한국 시간 09:00·14:00·19:00은 UTC `0 0,5,10 * * *`에 해당합니다. 재연결은 새로운 요청과 운영 인증·전체 원본 dry-run 검증이 필요합니다.

수동 실행 기본값은 dry-run입니다. 테스트를 먼저 통과해야 동기화 단계로 진행하며, 같은 동기화 작업은 직렬로 실행됩니다. 쓰기 권한 없는 GitHub 토큰을 사용합니다. 승인된 운영 세션·위치 설정이 없거나 원본 전체 검증에 실패하면 예약 실행도 실패로 끝나며 기존 게시물의 상태를 보존합니다.
