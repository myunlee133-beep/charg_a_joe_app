# 퀘스트 지도 홈 · iOS 구현

기존 SwiftUI/KakaoMapsSDK 화면의 흰색 카드, 청록색 강조색, 둥근 핀과 버튼을 유지하면서 브라우저에서 검토한 홈 구성을 네이티브 앱에 옮겼다. 이번 변경 기준은 최신 `main`의 `dcc468c`이다. 첨부된 빵빵투어 대전 시안의 종류 아이콘, 은은한 색 배경, 둥근 흰색 카드와 정보 위계를 참고하되 기존 앱의 청록색을 유지했다.

## 화면과 시연 범위

- 홈 지도에는 퀘스트, 교내 식당, 분실물 거점, 교내순환 정류장을 표시한다. 상단 필터로 종류를 전환한다.
- 첨부 APK를 Appetize에서 직접 실행해 대전 빵맵의 축소·중간·확대·핀 선택 상태를 비교했다. 축소하면 숫자 군집, 확대하면 개별 아이콘, 선택하면 이름표와 하단 카드가 드러나는 흐름을 반영했다. 고정된 큰 보상 말풍선은 제거했다.
- 홈은 레벨 15와 접힌 퀘스트 목록으로 시작한다. 레벨 14 이하는 작은 표식/숫자, 15~16은 종류 아이콘, 17은 짧은 보상 표시, 18 이상은 장소와 보상을 표시한다. 군집은 현재 배율의 화면 거리에 맞춰 분리된다. 같은 위치에 여러 퀘스트가 있으면 최대 확대에서도 목록으로 모두 접근할 수 있다. +/− 버튼과 숫자 군집 선택으로 확대할 수 있다. 핀을 선택하면 지도는 유지하고 선택한 퀘스트의 하단 미리보기와 상세 보기 버튼을 표시한다. 배율별 실제 마커 크기에 맞춰 탭 영역도 변경한다.
- 독립 퀘스트 탭에서 종류·보상 방식 필터, 검색, 가까운순/보상순, 등록, 상세, 내 퀘스트를 이용한다. 홈의 전체 보기 버튼으로도 이동한다. 하단 목록은 핸들을 누르거나 위로 끌어 펼친다. 선착순/결과 보상 필터, 가까운순/보상순, 상세, 등록, 내 퀘스트를 지원한다. 표시 거리는 학생회관을 기준으로 한 시연 값이다.
- 선착순 퀘스트는 한 번 수락할 수 있고, 결과 보상 퀘스트는 10자 이상의 결과를 제출할 수 있다. 이 상태와 새 등록 내용은 현재 앱 실행 중에만 유지한다. 다중 사용자 선착순 확정, 요청자 검수, 파일 전달, 계정, 결제·정산은 연결하지 않았다. 화면에도 시연 범위를 표시한다.
- 퀘스트와 식당을 함께 볼 때는 실제 화면의 식당 아이콘·이름표 크기를 기준으로 충돌을 계산한다. 퀘스트 표시를 가장 가까운 빈 공간으로 이동하고 원래 위치는 얇은 연결선으로 표시한다. 지도 좌표는 변경하지 않으며 확대·축소·이동 후 배치와 탭 영역을 다시 계산한다. 다른 퀘스트와의 충돌도 피하고, 선택한 퀘스트를 우선 배치한다. 식당과 퀘스트 모두 직접 선택할 수 있다.
- 홈 식당 카드는 위치와 식당 탭으로의 이동만 제공한다. 기존 식단·날짜·즐겨찾기 UI는 하단 식당 탭에서 사용한다.
- 하단에는 홈, 퀘스트, 식당, 분실물, 사랑방, 내 정보 6개 탭을 모두 노출한다. 방문한 화면을 유지하는 컨테이너로 시스템 TabView의 5개 초과 시 더 보기 전환을 피하고 검색·스크롤·로그인 상태를 보존한다. 숨겨진 홈에서는 GPS와 셔틀 추적을 중지한다.
- 기존 분실물 등록·수령 기능, 건물 검색, GPS·방향 표시와 사용자가 누를 때만 이동하는 현재 위치 버튼은 유지한다.

## 기능별 관리

이 문서와 `codex/quest`는 퀘스트 탭·지도 표시·식당과의 겹침 방지를 관리한다. 셔틀 추적기와 위치 갱신 서비스는 이 브랜치에서 변경하지 않는다. 셔틀 연속 이동은 원본 저장소의 [`codex/shuttle`](https://github.com/myunlee133-beep/charg_a_joe_app/tree/codex/shuttle) 브랜치와 [셔틀 문서](https://github.com/myunlee133-beep/charg_a_joe_app/blob/codex/shuttle/design-drafts/shuttle/README.md)에서 관리한다.

## 검증

루트에서 `swift test`로 모델 테스트 21개를 실행한다. 기존 셔틀 회귀 검사와 퀘스트 수락·제출 검사에 더해, 모든 배율의 퀘스트 보존·결정적 군집·정보 단계·그리드 경계 이웃·동일 좌표 접근·연쇄 군집 방지, 동일 위치의 식당·퀘스트 분리, 여러 퀘스트의 결정적 배치, 확대 단계·화면 경계·필터 변경 시 재배치, 회전한 지도의 화면 투영을 검사한다.

GitHub Actions는 macOS에서 위 테스트와 서명 없는 iOS Simulator 빌드를 실행한다. codex 브랜치 push와 수동 실행(`workflow_dispatch`)에서는 시뮬레이터에 앱을 설치·실행한 홈·16/17/18레벨 지도·선택한 퀘스트 미리보기·퀘스트 탭 화면을 `native-home-preview` 아티팩트로 저장한다. 같은 빌드를 `Chajajwo-simulator` 아티팩트로 패키징해 Appetize에서 검토할 수 있다. [초기 네이티브 홈 실행 캡처](https://github.com/yeongseo03/charg_a_joe_app/actions/runs/40548082560)의 실제 Kakao 지도, 퀘스트 목록과 6개 탭을 확인했다. 실기기 GPS 정확도와 실제 버스 이동 대조는 별도의 현장 확인이 필요하다.

수동 확인 순서:

1. 홈 지도 확대/축소 → 묶음/개별 퀘스트 선택 → 하단 핸들 펼치기.
2. 선착순 퀘스트 수락 → 재수락 불가, 결과 보상 퀘스트 결과 제출 → 확인 대기.
3. 건물 선택 후 시연 퀘스트 등록 → 지도와 내 정보의 내 퀘스트 확인.
4. 식당 마커 → 식당 탭에서 메뉴 확인 → 지도 복귀.
5. 셔틀 필터 → 14개 정류장과 실시간 조회 상태 확인. 실제 운행 중 차량 위치 변화와 도로 방향 대조.
6. 6개 탭을 모두 전환하고 검색·스크롤·로그인 상태 유지, 기존 습득물/신고/수령 흐름, 건물 검색, 현재 위치 버튼 확인.

빌드는 `ios/Chajajwo.xcodeproj`를 사용한다. 기존 `ios/project.yml`의 소스 경로도 새 Swift 파일과 리소스를 포함하므로 XcodeGen으로 재생성할 수 있다. 앱 키와 서명 설정은 기존 프로젝트 설정을 사용한다.
