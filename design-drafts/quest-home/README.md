# 퀘스트 지도 홈 · iOS 구현

기존 SwiftUI/KakaoMapsSDK 화면의 흰색 카드, 청록색 강조색, 둥근 핀과 버튼을 유지하면서 브라우저에서 검토한 홈 구성을 네이티브 앱에 옮겼다. 기준은 GPS 기능이 병합된 `main`의 `b6eeb3ecf87c050dbd7d144829fce22d49d76a07`이다.

## 화면과 시연 범위

- 홈 지도에는 퀘스트, 교내 식당, 분실물 거점, 교내순환 정류장을 표시한다. 상단 필터로 종류를 전환한다.
- 퀘스트는 지도 레벨 17 미만에서 지역별로 묶고, 확대하면 개별 보상 마커를 표시한다. 묶음을 누르면 지도를 확대한다.
- 하단 목록은 핸들을 누르거나 위로 끌어 펼친다. 선착순/결과 보상 필터, 가까운순/보상순, 상세, 등록, 내 퀘스트를 지원한다. 표시 거리는 학생회관을 기준으로 한 시연 값이다.
- 선착순 퀘스트는 한 번 수락할 수 있고, 결과 보상 퀘스트는 10자 이상의 결과를 제출할 수 있다. 이 상태와 새 등록 내용은 현재 앱 실행 중에만 유지한다. 다중 사용자 선착순 확정, 요청자 검수, 파일 전달, 계정, 결제·정산은 연결하지 않았다. 화면에도 시연 범위를 표시한다.
- 홈 식당 카드는 위치와 식당 탭으로의 이동만 제공한다. 기존 식단·날짜·즐겨찾기 UI는 하단 식당 탭에서 사용한다.
- 하단에는 홈, 식당, 분실물, 신고, 커뮤니티, 내 정보를 모두 노출한다. 커뮤니티 본문은 비워 두었다.
- 기존 분실물 등록·수령 기능, 건물 검색, GPS·방향 표시와 사용자가 누를 때만 이동하는 현재 위치 버튼은 유지한다.

## 교내순환 실시간 위치

요청 노선은 `41946` 한 개다. Android 앱과 같은 공개 조회 주소인 `https://chajajwo-web-mu.vercel.app/api/shuttle?route=41946`를 약 5초마다 읽는다. 응답을 받은 뒤 다음 조회까지 5초를 기다리며 요청 제한 시간은 7초다. 앱이 활성 상태이고 홈의 전체/셔틀 필터를 보고 있을 때만 조회한다. 오류, 빈 응답, 다른 노선, 오래된 응답에서는 차량을 임의로 생성하지 않는다.

추정 로직은 [Android 저장소](https://github.com/yeongseo03/chargajoe_android)의 `c24d05c42389b40fdf3562f05eabad6ead8e6494`에 있는 `ShuttleTracker.java`와 검토한 브라우저 구현을 참고했다. 운영사의 원본은 `https://web.busin.co.kr/BuslineCircleS.aspx/GetRoute`의 `{ "data": ",F,41946,snu_1" }` 응답이다.

1. 운영사가 제공하는 차량 ID와 노선도 x/y를 14개 정류장의 노선도 구간에 투영한다. 이전 진행 위치를 함께 고려해 가까운 다른 구간으로 잘못 넘어가는 현상을 줄인다.
2. 구간 진행률을 번들 도로 경로에 대응한다. 도로 좌표는 OpenStreetMap 기반이며 정류장 기준점과 도로의 차이는 테스트에서 35m 이내인지 확인한다. © OpenStreetMap contributors, [ODbL](https://www.openstreetmap.org/copyright).
3. 24px를 넘는 투영 오차, 과도한 후진·도약을 걸러낸다. 0.7px 미만의 변화는 누적하고, 5px 이내 후진 흔들림은 위치를 뒤로 이동시키지 않는다. 픽셀 판정과 별도로 도로상 15m/s + 35m 여유 범위를 적용한다. 잘못된 관측은 숨기되 같은 차량의 정상 이력은 유지한다.
4. 새 관측을 받으면 1.2초 동안 도로를 따라 보간하고 차체를 진행 방향으로 회전한다. 이후의 위치는 외삽하지 않는다. 변화 없는 좌표를 수신했다고 계속 달리는 애니메이션을 만들지 않는다.
5. 차량이 사라지거나 마지막 정상 관측이 20초 이상 지나면 숨긴다. 앱이 백그라운드로 가거나 해당 지도를 벗어나면 요청과 보간을 중지한다.

**정확도 한계:** 응답 좌표는 GPS 위경도가 아니다. 정류장 사이 실제 이동과 노선도 이동 비율이 항상 같다고 보장할 수 없고, 운영사 좌표의 실제 측정 시각도 제공되지 않는다. `checkedAt`은 조회 시각으로만 표시한다. 실제 운행 차량의 GPS와 대조한 미터 단위 정확도는 검증하지 못했다. 2026-10-28 02:05 KST 조회에서는 HTTP 200과 빈 `vehicles` 배열을 받았으며, 이는 위치 데이터가 반환되지 않았다는 의미다. 운행 대수가 0대라고 단정하지 않는다.

도착예정시간 역시 현재 응답에서 제공하지 않는다. 기존의 임의 `3/13/23분` 데이터는 제거하고 제공 여부를 안내한다. 이 구현에는 가상 버스나 예시 도착시간 모드가 없다.

## 검증

루트에서 `swift test`로 퀘스트 상태와 추적 모델 테스트 12개를 실행한다. 정류장 기준점, 정지한 좌표, 1.2초 보간 종료, 작은 변화 누적, 후진·점프 거부, 비정상 관측 뒤 이력 복구, 누락·지연 제거, 한 바퀴 경계, 잘못된 노선/시각, 중복 수락·제출, 확대 시 퀘스트 보존을 검사한다.

GitHub Actions는 macOS에서 위 테스트와 서명 없는 iOS Simulator 빌드를 실행한다. 시뮬레이터에 앱을 설치·실행한 홈 화면은 `native-home-preview` 아티팩트로 저장한다. 실기기 GPS 정확도와 실제 버스 이동 대조는 별도의 현장 확인이 필요하다.

수동 확인 순서:

1. 홈 지도 확대/축소 → 묶음/개별 퀘스트 선택 → 하단 핸들 펼치기.
2. 선착순 퀘스트 수락 → 재수락 불가, 결과 보상 퀘스트 결과 제출 → 확인 대기.
3. 건물 선택 후 시연 퀘스트 등록 → 지도와 내 정보의 내 퀘스트 확인.
4. 식당 마커 → 식당 탭에서 메뉴 확인 → 지도 복귀.
5. 셔틀 필터 → 14개 정류장과 실시간 조회 상태 확인. 실제 운행 중 차량 위치 변화와 도로 방향 대조.
6. 커뮤니티 빈 본문, 기존 습득물/신고/수령 흐름, 건물 검색, 현재 위치 버튼 확인.

빌드는 `ios/Chajajwo.xcodeproj`를 사용한다. 기존 `ios/project.yml`의 소스 경로도 새 Swift 파일과 리소스를 포함하므로 XcodeGen으로 재생성할 수 있다. 앱 키와 서명 설정은 기존 프로젝트 설정을 사용한다.
