# 교내순환 셔틀 연속 이동

원본 저장소의 `codex/shuttle`에서 위치 추적과 연속 이동만 관리한다. 퀘스트 탭과 지도 이름표 변경은 `codex/quest`에서 관리한다. 두 브랜치는 최신 `main`의 `dcc468c`를 공통 기준으로 독립적으로 검토·병합할 수 있다.

## 동작

- `41946` 노선의 기존 실시간 조회 주소를 사용한다. 요청 시작 기준 약 5초 간격이며 요청에 걸린 시간은 다음 대기에서 뺀다.
- 정상 관측을 받으면 현재 화면 위치에서 확인된 도로 구간을 따라 일정한 진행률로 이동한다. 보간 시간은 이동 관측 간격에 맞춘 5~30초다. 큰 정류장 간 갱신도 순간 이동시키지 않는다.
- 20fps 프레임 갱신은 조회와 독립적으로 유지한다. 같은 좌표를 반복 수신하거나 요청이 진행 중이어도 기존 보간을 초기화하지 않는다. 새 이동은 현재 표시 위치에서 이어진다.
- 다음 정류장은 현재 표시 중인 도로 위치를 기준으로 계산한다. 지도 POI만 갱신하므로 SwiftUI 화면 전체를 매 프레임 다시 만들지 않는다.
- 마지막 확인 위치를 넘어 외삽하지 않는다. 입력이 바뀌지 않으면 보간 완료 후 멈춘다. 기존 잘못된 좌표·후진·속도·오래된 관측 거부와 생명주기 중지는 유지한다.

원본은 GPS 위경도가 아닌 운영사 노선도 좌표다. 표시에는 최대 30초 보간 지연이 있을 수 있으며 실기기 GPS 정확도와 실제 운행 차량의 위치 대조는 별도 확인이 필요하다.

## 검증

`swift test`로 기존 퀘스트 상태 검사와 셔틀 회귀 검사를 포함한 테스트 14개를 실행한다. 연속 200프레임의 이동·새 수신 시 위치 연속성·정류장 간 30초 보간·반복 수신·보간 종료 후 정지·잘못된 관측·누락과 지연·한 바퀴 경계를 검사한다. GitHub Actions에서 이 브랜치의 모델 테스트와 iOS Simulator 빌드를 확인한다.

기존 PR #8과 브랜치 이력을 유지한 채 최신 연속 이동 구현을 추가했다. 기능별 브랜치 전체 구성은 [`docs/feature-branches.md`](../../docs/feature-branches.md)를 참고한다.
